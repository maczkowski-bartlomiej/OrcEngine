# Enforce Universal Fail-Fast Error Handling Across All Subsystems

Error handling across `OrcEngine` previously mixed multiple conflicting models: `Scripting` and XML manifest loading in `ResourceHolder` aborted via `ORC_FATAL_CHECK`; `Window` and `Gui` logged `ORC_LOG_FATAL` and returned early, leaving the engine in a half-initialized state; `Audio`, `Font`, `Shader`, `Texture`, `Animator`, `GameLayerManager`, and `ResourceHolder` asset lookups logged `ORC_LOG_ERROR` and returned `false` or `nullptr` (while asset and window constructors ignored those `bool` return values); precondition checks in `Renderer`, `VertexArray`, `GameLayerManager`, `Bus`, and `Event` used debug-only `ORC_ASSERT` that compiled out in Release builds; and SDK wrappers (`fmodCall` and `ftCall`) returned `bool` and required `fmt::format` call-site boilerplate.

We decided to adopt a single, universal **Fail-Fast Crash Contract** across the entire engine:
- **Unconditional `ORC_FATAL_CHECK` and `ORC_FATAL` Only**: `Orc/Engine/Debug.hpp` provides only `ORC_FATAL_CHECK(check, message, ...)` and `ORC_FATAL(message, ...)`, which log via `ORC_LOG_FATAL`, trigger `ORC_DEBUGBREAK()` in Debug builds, and call `std::abort()` in both Debug and Release configurations. `ORC_ASSERT`, `ORC_WARNING`, `ORC_ERROR`, `ORC_ERROR_CHECK`, and standalone `ORC_LOG_ERROR` are removed. Both macros remain preprocessor definitions rather than functions so format arguments (such as error-string lookups and path conversions) are lazily evaluated only when a check fails and `ORC_DEBUGBREAK()` halts on the exact caller line.
- **Zero-Boilerplate SDK Call Macros (`ORC_FMOD_CALL` and `ORC_FT_CALL`)**: `AudioUtility.hpp` and `FontUtility.hpp` define `ORC_FMOD_CALL(call, message, ...)` and `ORC_FT_CALL(call, message, ...)` macros that delegate directly to `ORC_FATAL_CHECK` using string literal concatenation (`message "\n\tFMOD Error: {}"` / `message "\n\tFreeType Error: {}"`), eliminating `fmt::format` call-site allocations and local result variables.
- **Guaranteed Valid State & `void` / `const Ref<T>&` Signatures**: Because reaching an invalid state during subsystem bootstrap, asset loading, manifest parsing, resource lookup, or runtime rendering/audio/animation calls immediately terminates the process, initialization and loading methods (`Logger::init`, `Window::initGLAD`, `Font::loadFromFile`, `Shader::loadFromFile`, `Shader::loadFromString`, `Shader::readShader`, `Shader::compile`, `Texture::loadFromFile`, `Texture::loadFromMemory`, `Resources::loadResources`) return `void`, and `Resources::getResource` returns `const Ref<ResourceType>&`. All defensive half-initialized state guards (such as `if (!m_system)` in `Audio`) and redundant post-call out-pointer checks (where the SDK return code already guarantees validity) are eliminated.
- **`ORC_LOG_WARNING` Strictly for Benign Valid-State Notices**: `ORC_LOG_WARNING` is reserved for non-fatal occurrences where engine invariants remain intact (such as requesting a switch to the already-active `GameLayer` or requesting a non-ASCII character code from `Font` that resolves to a fallback glyph).
