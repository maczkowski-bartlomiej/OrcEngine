# Revert to Polymorphic Event Hierarchy

> [!NOTE]
> Superseded by [ADR 0010](0010-deepen-input-and-collapse-event-to-pure-enum.md).

OrcEngine previously wrapped window and input events in a closed `std::variant`-based value wrapper (`EventVariant`), which required `Event.hpp` to include all concrete event headers, introduced template visitation bloat (`event.visit`, `Overload`, `EventDispatcher`), and carried unused mutable state (`m_handled`, `setHandled()`, `isHandled()`). We decided to revert `Event` to a lightweight polymorphic base class containing an `Event::Type` tag, an explicit single-argument constructor, and a virtual destructor, with concrete event structs inheriting from `Event` and declaring plain, non-const fields. Downcasting is provided by the free template function `getEvent<T>(event)`, which verifies the cast via an RTTI assertion (`dynamic_cast`) in debug builds and uses `static_cast` with zero runtime overhead in release. Subsystem event handling (`Input::onEvent`, `GameLayer::onEvent`, `Engine::onEvent`) is cleanly expressed using standard `switch` or `if` statements over `event.getType()`. This eliminates circular header dependencies, simplifies control flow, and reduces compile times while maintaining safe downcasting and explicit subsystem decoupling.

As an architectural trade-off, moving away from `std::variant` foregoes compile-time pattern-match exhaustiveness checking in exchange for open extensibility, and introducing a virtual destructor adds a vtable pointer to event objects (which is leveraged for debug RTTI downcast assertions while remaining zero-overhead in release).
