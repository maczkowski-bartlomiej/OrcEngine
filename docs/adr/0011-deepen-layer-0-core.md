# Deepen Layer 0 Core Architecture and Seal Third-Party Diagnostics

Layer 0 (`Core`) in `OrcEngine` is designed to be the foundational module providing universal engine primitives with zero upward dependencies, while `Engine` serves as the high-level coordinator over domain subsystems (`Events`, `Input`, `Graphics`, `Audio`, `Scripting`). Previously, this layering invariant was compromised:
- `Logger` and `Debug` resided in `Engine`, forcing every subsystem and `OrcPch.hpp` to include upward into `Engine` and creating circular architectural dependency cycles.
- `Logger` leaked third-party `<spdlog/logger.h>` and `<spdlog/fmt/fmt.h>` across public headers and included GLM math types purely for `FilePath`. `Debug` duplicated `ORC_FATAL` and `ORC_FATAL_CHECK` macros across `#ifdef ORC_DEBUG_ASSERTS` branches.
- `Engine` contained a shallow `Utility` grab-bag (`StringViewHash` and a single-caller `getErrnoMessage` wrapper), while foundational primitives `Clock` and `Random` were misplaced in `Engine` (with `Random::getSeed()` returning a stale `0` prior to an explicit `setSeed()` call).
- `ORC_FT_CALL` was isolated in a 12-line single-caller header `FontUtility.hpp` requiring convention-linter workarounds.
- `Rect<T>` stored width and height inside public fields named `right` and `bottom`, contradicting its constructor `(x, y, width, height)` and requiring awkward workarounds across `Texturable`, `Sprite`, `Text`, `Camera`, and manifest loading.

We decided to purify and deepen Layer 0 (`Core`) by establishing strict downward dependency flow and clean module boundaries:
- **Relocate Diagnostics to `Core` and Seal `spdlog`**: `Logger` and `Debug` move from `Engine` into `Core`. `Logger::log` delegates through a non-template `Logger::logImpl(Level level, std::source_location sourceLocation, fmt::string_view format, fmt::format_args args)` seam, isolating `spdlog::logger` inside `Logger.cpp` and removing `<spdlog/logger.h>` entirely from public headers. In CMake, `spdlog::spdlog` is linked `PRIVATE` on `OrcEngine`, and `Logger.hpp` references `<filesystem>` directly without pulling in GLM math types. `Debug` unifies `ORC_FATAL` and `ORC_FATAL_CHECK` into a single macro definition relying on `ORC_DEBUGBREAK()` expanding to a no-op when debug asserts are disabled.
- **Dissolve `Utility` Grab-Bag and Move Primitives to `Core`**: The shallow `Utility` module is eliminated. `StringViewHash` moves to `Core/StringViewHash.hpp` for transparent heterogeneous map lookups, and shader file error reporting calls `std::system_category().message(errno)` directly. `Clock` and `Random` move into `Core`, with `Random` initializing `m_seed = std::random_device{}()` first and seeding `m_engine` from `m_seed` so `Random::getSeed()` is always truthful.
- **Inline `FontUtility` and Repair `Rect<T>` Field Semantics**: `ORC_FT_CALL` is defined locally inside `Font.cpp`, deleting `FontUtility.hpp` and removing its linter exemption. `Rect<T>` (`IntRect`, `FloatRect`) relocates into `Core/Rect.hpp` with fields named `left, top, width, height`. Constructor semantics, `getSize()`, and `intersects()` align with `width` and `height`, and all callers across `Texturable`, `Camera`, `Sprite`, `Text`, and `ResourceHolder` use `.width` and `.height` cleanly.

As a result, all Layer 1 subsystems (`Events`, `Input`, `Graphics`, `Audio`, `Script`) and `OrcPch.hpp` depend strictly downward on `Core` with zero upward `#include "Engine/..."` directives. Third-party logging internals are completely sealed within engine implementation files, and foundational geometric and time primitives are universally available without lifecycle coordination baggage.
