# Modernize Scripting Subsystem with .NET 10 CoreCLR via Hostfxr

The engine originally used an embedded Mono runtime for C# scripting. However, Mono required external SDK installations, lacked modern C# language features and runtime optimizations, and suffered from brittle assembly search path resolution. Initial migration experiments with .NET 10 CoreCLR directly exposed raw native handles, used global mutable function pointers, relied on preprocessor macros, and implemented permissive error handling that logged warnings and returned `false` on missing dependencies, leading to late crashes or undefined behavior.

We decided to replace the legacy Mono runtime with a hardened, modern .NET 10 CoreCLR hosting architecture via Microsoft's `hostfxr` APIs:
- **Fail-Fast Crash Contract**: Any failure in the hosting sequence—locating hostfxr, loading the dynamic library, resolving hosting delegates, loading the runtime configuration, loading managed assemblies, or binding entry points—immediately triggers an unconditional fatal error (`ORC_LOG_FATAL`), debugger break (`ORC_DEBUGBREAK()`), and process termination (`std::abort()`). This ensures misconfigurations or missing assemblies are caught at launch time rather than failing silently.
- **PIMPL Encapsulation**: `Orc/Script/Scripting.hpp` encapsulates all platform dynamic library handles (`HMODULE` / `void*`), hostfxr function pointers, and CoreCLR delegates within an opaque `UniquePtr<Impl>`. Public engine headers are completely decoupled from operating system headers (`Windows.h`, `dlfcn.h`) and .NET hosting headers (`nethost.h`, `hostfxr.h`, `coreclr_delegates.h`).
- **Rule of 5 and Universal Path Semantics**: Copy operations on `Scripting` are explicitly deleted to prevent native handle duplication and double-freeing; move operations are explicitly supported. File path parameters adhere to the engine's canonical `const FilePath&` alias passing convention.
- **Type-Safe Static C++ Helpers**: Replaced preprocessor macros (`ORC_LOAD_LIB`, `ORC_GET_EXPORT`, `ORC_FREE_LIB`, `ORC_DOTNET_STR`) with static C++ helper functions (`loadLibrary`, `getExport`, `freeLibrary`, `toPalString`) and template helpers (`getRuntimeDelegate<T>`, `getManagedFunction<T>`).
- **`[UnmanagedCallersOnly]` Interop**: Managed C# functions are marked with `[UnmanagedCallersOnly]` in C# and resolved via `load_assembly_and_get_function_pointer`, providing zero-overhead direct function pointer invocation without reverse P/Invoke marshalling wrappers.
- **Nomenclature Synchronization**: Stale Mono identifiers in `Engine` (`m_mono`) were renamed to canonical `Scripting` (`m_scripting`), aligning code and documentation with ubiquitous language.
